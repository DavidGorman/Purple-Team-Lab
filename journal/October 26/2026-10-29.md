# Repository Housekeeping Before Going Public

**Phase:** Plan
**Time spent:** 1 hour 

## Goal

Get the repository ready to be made public as a portfolio piece, without exposing anything personal or sensitive.

## What I did

- Audited every tracked file and the full commit history for IP addresses, emails, tokens and passwords. Lab addresses are private ranges in an isolated lab and stay. Nothing sensitive found in file contents
- Found my personal email in the author metadata of every commit, because local Git was configured with it (GitHub's "keep email private" setting only covers web commits)
- Switched Git to my GitHub noreply address and turned on "Block command line pushes that expose my email"
- Rewrote the existing commits to the noreply address, keeping dates and messages, and force pushed
- Reviewed screenshots in `evidence/`, including one only present in history
- Decided what stays private: working notes for live systems and personal command notes are now in `.gitignore`. Only the isolated lab and finished write-ups get published

```bash
# Use the noreply address for all future commits
git config --global user.email "<GITHUB_NOREPLY_EMAIL>"

# Rewrite author and committer email on every commit (all commits are mine)
git filter-branch -f --env-filter 'export GIT_AUTHOR_EMAIL="<GITHUB_NOREPLY_EMAIL>"; export GIT_COMMITTER_EMAIL="<GITHUB_NOREPLY_EMAIL>"' -- --all

# Remove filter-branch's backups so the old commits are really gone locally
git for-each-ref --format="%(refname)"
git update-ref -d refs/original/refs/remotes/origin/main
git reflog expire --expire=now --all
git gc --prune=now

# Verify, then confirm GitHub matches local
git log --all --format="%an <%ae>" | sort -u
git push --force --all origin
git rev-parse main
git ls-remote origin main
```

## Problems and fixes

| Problem | Cause | Fix |
| --- | --- | --- |
| `pip install git-filter-repo` refused (externally managed environment) | The Python on PATH is Git Bash's MSYS2 Python | Used Git's built-in `filter-branch` instead |
| Command hung at a `>` prompt | Ran a PowerShell command (backtick newline) in Git Bash | Ctrl+C, used `printf` instead |
| Old email still showed in `git log --all` after rewriting | filter-branch kept a backup under `refs/original/` | Deleted the ref, expired the reflog, ran gc |
| Push said "Everything up-to-date" but old email still visible | Same leftover local ref, not the remote | Confirmed with `git ls-remote` that GitHub had the new history |
