# Firewall Policy, Rule Set and First pfSense Rules

**Phase:** Build
**Time spent:**

## Goal

Design the firewall the realistic way: write a network security policy, turn it into a rule set, then start implementing it on fw01.

## What I did

**Design decisions**

- Zones: LAN (dc01, workstations), DMZ (web01), MGMT (siem01, treated as the SOC), VPN, WAN
- Default deny between zones; only service traffic (SIEM agents, DNS, NTP, web) crosses the firewall directly. People crossing zones for admin come in through the VPN
- No DMZ to LAN traffic at all in the baseline. The attack path will be introduced later as a recorded exception, so the hardening phase can show it being closed
- web01's web service is published to WAN; LAN reaches it through NAT reflection, the same way the public does
- siem01 is out of scope for attacks; MGMT is console-only (no remote path to the SIEM)
- One VPN for now (OpenVPN, full tunnel, 10.10.40.0/24)
- Kali stays on VMnet8 for now. Moving it to its own segment behind fw01 is parked as a later option

**Documents**

- `docs/network-security-policy.md` (v0.2): zones, principles, inter-zone matrix, policy statements with IDs (P-LAN-01 etc.), remote and admin access, logging, accepted risks (R-01: web01 agent channel into MGMT), exception process, change control
- `docs/firewall-rules.md`: addressing, aliases, interface settings, NAT, and a rule table per interface. Every rule names the policy statement it implements

**pfSense implementation (fw01)**

1. Backed up the config and captured the default rules as the "before" state
2. Created aliases: hosts `web01`, `dc01`, `siem01`; network `RFC1918`; ports `Web_Ports`, `Wazuh_Agent`, `Wazuh_Enrol`, `Win_Admin`
3. WAN: unticked "Block private networks", because the simulated internet (VMnet8) is 192.168.1.0/24
4. NAT port forward WAN address:Web_Ports to web01:Web_Ports (P-WAN-02), with an associated WAN filter rule and logging on
5. Tested from Kali. web01 is down, so the connection times out, but the firewall log shows the forward working: pass on WAN, 192.168.1.136 to 10.10.10.10:80, rule "NAT P-WAN-02"

```bash
# From kali
curl -m 5 http://192.168.1.10
# curl: (28) Connection timed out after 5043 milliseconds  (expected, web01 is down)
```

## Problems and fixes

| Problem | Cause | Fix |
| --- | --- | --- |
| `Web_Ports` not listed in the NAT port dropdown | The dropdown only holds pfSense's built-in ports | Set the dropdown to Other and type the alias name in the Custom box |
| SIEM agents can't go through a VPN | First draft said all inter-subnet traffic must use the VPN | Split into service traffic (direct, specific ports) and admin traffic (VPN only) |
| No policy statement for some rules | MGMT DNS/NTP and VPN DNS weren't covered | Added P-MGT-04 and P-VPN-06; limited P-LAN-04 to the DC |
